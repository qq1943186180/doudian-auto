# ego 原生浏览器链路实测

日期：2026-10-29。范围：比较当前程序可用的 ego(lite) 原生浏览器执行通道；通过妙手 UI 对一件仓库商品测试 5 张主图、4 张详情图上传与预览，并在妙手、抖店各重读一次。此结果只覆盖读、上传暂存、预览和核对，不覆盖商品保存。

## 结果

- 两个店铺页面登录后均可读。整个任务使用同一个 Ego TaskSpace；妙手、抖店页面分配到独立的 p1、p2，可按自己的 TaskSpace 精确收尾。
- 5 张主图及 4 张详情图使用商品原图上传。每个目标槽位读回临时 CDN 地址后，抓取远端文件并与本地 SHA-256 比对，9/9 字节完全一致。临时 CDN 地址不等于商品已保存。
- 妙手“预览修改效果”显示新标题、新 5 张主图和新前 4 张详情图；原详情图共 14 张，尾部 10 张顺序保留。预览对比图文字及图片槽位均经完整页面 DOM 读取核对。
- 上传与预览过程中没有调用“保存修改”或“开始批量修改”。关闭预览、重新查询妙手、重新加载抖店编辑页后，标题、商品图片身份和商业保护字段都与基线相同。保存尝试数为 0。
- 初期以 CDN 完整 URL 字符串直接比对，会把 `p3`、`p9` 图片加速域名误报为变化；应比较 `ecom-shop-material` 下对象路径并保留序号。
- 抖店重载后，运费模板在表单快照中的展示文案从“非偏远”变为选项 ID `414163746`；妙手原始商品数据中的 `freightId` 正是该值。页面加载后两个空区块从 `empty_block` 变成 `ready`，但输入、选项、图片和静态字段均为空。只在这两种可证实等价的表示下归一化后，基线与读回 SHA-256 相同，其他保护字段逐项一致。

## 分段计时

以下是页面内可重复测量的子步骤，不是端到端人工耗时或 Edge 对照：

| 步骤 | 耗时 |
|---|---:|
| 妙手单品查询 | 2.264 秒 |
| 妙手商品完整基线读取 | 2.274 秒 |
| 妙手商品复读 | 2.140 秒 |
| 单品预览 | 1.388 秒 |
| 9 张原图上传并远端读回 | 合计约 26.5 秒，单张 1.647–4.355 秒 |
| 抖店页面完整字段 DOM 快照 | 首次实测约 22 毫秒（商品编辑页已加载后） |

浏览器框架自动将深处控件滚动到视口时，个别编辑页动作仍花数秒；这次对比不能证明 Ego 的整个商品编辑流程比 Edge 更快。它证明了 Ego 原生任务页稳定绑定，不再出现此前 Kimi 服务在 Edge 和 Ego 扩展之间切换的连接冲突。可作为后续单写入器的默认浏览器通道，再用同一批商品与固定步骤做 Edge 对照。

## 操作约束与已知问题

- 详情图原图选择器和替换图上传共用 `.select-product-filter-dialog`，主图上传使用 `.replace-image-dialog`。程序应根据槽位类型等待正确弹窗和可见 file input；不能把主图弹窗适配直接复制到详情。
- 上传成功后图片选择弹窗可能自动关闭。文件上传、目标槽位 URL 及字节核验完成后，先等待弹窗关闭；只有它仍可见且关闭按钮有有效尺寸时才执行关闭，避免对已消失的对话框重试。
- 页面每个 Node round 都是新进程；TaskSpace 与 Page 标签可恢复，事件缓冲区不能跨 round 保留。每轮以最新页面快照为依据；要采集网络事件，应先启用 Network 并在触发动作的同一轮读取事件。
- Ego 窗口最小化时截图 API 报错；本次依照完整 DOM 预览和独立读回验收，没有把无法截图误判为商品操作失败。需要视觉截图时，窗口须处于非最小化状态。
- 已生成候选图的腰头印字或球体孔位存在身份偏差，未获准进入写入流程。本次使用原图只验证上传和预览；不能据此放开商品保存。

## 对程序的影响

后续 `doudian-auto` 继续保留 SQLite 持久化队列和单写入器，将 Ego TaskSpace 作为页面控制传输的候选默认实现。提交前仍须：验证所选商品的生成素材身份；持久化唯一提交意图；在妙手只点击一次保存；收到结果后独立重读抖店并比较完整保护字段；处理结果未知时只读恢复。通用 writer 保持关闭，直至保存受理、保存后双端核验和三件完整连续验收完成。
