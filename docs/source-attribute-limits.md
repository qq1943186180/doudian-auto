# 类目属性的事实边界

最后核实：2026-11-11。依据是对 1688 源页面完整属性区的实测，以及抖店编辑页的真实选项集。

## 为什么要写这份

抖店发商品时要求类目属性。本项目从 1688 铺货，直觉上「源头页面应该有这些属性」。
实测结论相反：**有一类属性源头根本没有**，反复去读只会浪费时间，还可能误把别处的值
当成事实填进商品。这份文档把边界钉死，避免下次重走。

## 1688 商品属性区实际包含什么

对 5 件不同类目的商品完整读取，属性区**只有**以下字段，无一例外：

材质、品牌、贸易属性、是否进口、箱装数量、加工定制、专利、货号、颜色、规格、
产地、是否跨境出口专供货源。

另外有「商品件重尺」表，给出**包装**的长/宽/高/体积/重量。包装尺寸不是商品尺寸，
不能拿来填「尺寸」。

## 抖店独有、源头没有的属性

| 抖店属性 | 源头状态 | 说明 |
|---|---|---|
| 安装方式 | 无 | 抖店类目特有。1688 详情图为营销图，无安装说明 |
| 尺寸 | 无 | 只有包装件重尺，非商品本体尺寸 |
| 厚度 | 无 | 属性区无此字段 |
| 硬度 | 无 | 属性区无此字段；抖店只有「软/硬」两选项 |
| 适用年龄 | 无 | 属性区无此字段；抖店为多选（最多 5 项） |

代码里由 `source_facts.DOUYIN_ONLY` 与 `needs_human()` 表达，调用方据此直接向用户提问，
不再重复读源页面。

## 能从源头确定的属性

| 抖店属性 | 来源 | 映射规则 |
|---|---|---|
| 型号 | 源「货号」 | 直接对应 |
| 是否进口 | 源「是否进口」 | 直接对应 |
| 材质 | 源「材质」 | 保留供应商原词，不转成抖店多选分类 |
| 产地 | 源页面地名 | 需页面上真有地名；公司名里的「市」不算地址 |

`咨询客服` 这类值是供应商拒绝给值，不是值，必须丢弃。

## 详情图不是参数来源

- **1688 详情图**：场景图、承重演示、结构特写。实测 13 张无一含尺寸参数表。
  唯一有用的是结构特写——能看出「吸盘吸附」这类物理安装方式，但**看不出平台要选哪个词**。
- **抖店详情图**：带「元宝AI生成」水印的 AI 营销图，不含任何参数。

## 标题关键词也不等于选项值

例：标题写「免打孔」，但该商品「安装方式」的选项集里没有「免打孔式」，只有
`壁挂式/台式/挂钩式/嵌入式/落地式/悬浮式/龙骨式/胶粘式/吸盘式/桌夹式/顶天立地式`。
「免打孔」是营销说法，「吸盘式」「胶粘式」才是平台分类。两者不能互相替代。

## 结论

这几类属性只能由熟悉实物的人提供，或实测商品本体。程序的责任是**把问题问准**：
列出该商品的实际选项集，而不是让用户面对一句「缺安装方式」。

## 已核实的案例

商品 50（3848315275342643596 免打孔吸盘抹布架）之所以能填「免打孔式」，是因为
它的选项集**恰好有**「免打孔式」，且标题与主图双证指向免打孔吸盘。这是运气，不是通例。
