## 点击无效先查对话框（2026-10-22 实测）

页面存在未保存修改时，导航或被拦截的提交会弹出 `beforeunload` 对话框。**该对话框打开期间，`click` 类命令会静默失效**：返回 success、不报错、不产生网络请求，而 `evaluate` 仍可执行——因此很容易误判为选择器错或组件不响应。

排查顺序：先确认 `evaluate` 是否可用 → 可用则检查是否有 `beforeunload` → 用 `dialog` 动作处理。这是本轮所有「点了没反应」的根因，但它不是此类现象的唯一可能原因；选择器过时、元素被重渲染替换、组件处于 loading 态同样会造成点击无效，需逐项排除。

不要统一写成「自动 accept」：接受离页可能丢弃未保存内容，处理方向取决于当时正在做什么（要继续编辑就 dismiss，要放弃重来才 accept）。

另有一类独立现象：平台的发布埋点接口会返回风控提示（`publishClickStat` → `{"code":"10001010A","msg":"当前环境存在风险，请稍后重试"}`）。遇到时不要连续重点，等待后再试。

## 修改类目（2026-10-22 实测路径）

平台推荐类目会在标题填写后或提交时给出。改类目的可复现路径：

1. 类目行右侧「修改」是 `div.style_modifyButton__M2W_6`，不在 button 列表里，按 button 角色查找会漏掉。
2. 弹「修改类目可能会导致部分内容丢失，确认修改？」→ 点「修改类目」。
3. 进入类目重选页，平台给出 3–5 个推荐类目（每次推荐集合可能不同）。点目标标签；已选态是 `styles_itemSelected__*`。也可「发起申请」走其他类目。
4. 点「下一步」返回完整编辑页，此时类目已变但**尚未持久化**。
5. **必须再点「保存草稿」**，否则刷新会回退到旧类目（实测踩过）。

改类目的连带影响：类目属性会被平台重置（本例 材质/服务内容/是否自带背胶/隔音产品 → 只剩品牌=无品牌），价格库存的可选项随类目变化。这些是类目变更的必然结果，不是意外改动，但要逐项记录并重新核对商业字段，不能概括成「什么都没变」。

## 分区可见性是延迟渲染，不能按位置比较

平台对 `权益`、`尺码表`、`尺码信息` 这类分区用 `style_hidden__cBzTt`（`visibility:hidden` + height 0）**延迟渲染**。可见集合随页面展开状态变化，两次读取可能一次 8 段、一次 5 段。按下标比较会让索引全部错位（`权益` 对上 `价格库存`），表现为「商业字段被改动」的误报。

正确做法：按稳定的分区标识（`goodsEditScrollContainer-<名称>`）对齐，并为每段记录观测状态 `ready / empty_block / unobserved`。`empty_block` 只在正面证据下成立（无 `[attr-field-id]`、无表单控件、无物料图、textContent 为空或仅自身标题）。**不可观测不等于空，也不等于未变**，只能报「无法确认」。

## 快照格式

由授权浏览器的只读DOM采集产生UTF-8 JSON：

```json
{
  "title": "商品标题",
  "sections": [{
    "id": "goodsEditScrollContainer-价格库存",
    "text": "实际可见分区文字，含SKU编号",
    "inputs": [{"value": "20.88", "type": "text"}],
    "images": [{"field": "主图", "src": "https://实际商品图片CDN/图片", "w": 1254, "h": 1254}]
  }]
}
```

采集各分区innerText、input当前值和类型、img的currentSrc或src及naturalWidth/Height；勿读取框架内部状态、Cookie或存储。虚拟表格若只渲染部分SKU，滚动采集或明确标示覆盖范围。
