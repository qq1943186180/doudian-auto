# 抖店单商品铺货

程序负责可重复的页面原子操作、持久化任务状态与安全闸门；Agent 负责核实商品事实、解释预检结果、取得人工确认并组织阶段执行。此流程是**单商品**流程，不是批量队列。

## 适用范围

仅用于通过 `doudian-auto dropship` 从 1688 来源商品铺货到指定抖店店铺。它不替代：

- 修改已存在的抖店商品：`doudian-product-workflow`
- 妙手持久化批量图文优化：`miaoshou-auto-batch`
- 妙手单个商品手工编辑：`miaoshou-product-workflow`

开始前确认来源商品 ID、与之匹配的 1688 商品链接、店铺、源价、倍数、加价，以及来源标题/已知类目。ID、链接或店铺不明时先查证，不猜测。

## 选品候选（只读）

```powershell
doudian-auto --json dropship candidates --session '<会话>' --limit 30
```

这会只读列出抖店「抖音官方机会商品」页的候选，默认只保留同时带「支持密文」和「一件代发」的卡片，附带标题、价格区间、商机词、服务标签。

🔴 **候选卡片本身不含 1688 offer ID，只有妙手内部 UUID**，所以这份清单本身不能直接用作 `prepare` 的链接。

但**这条路径不是没有来源身份**：在机会商品页点某个卡片的「立即铺货」，页面会展开一个复制预览抽屉，抽屉里会给出该商品的**精确 1688 offer ID 与链接**（程序也会从那里读出来）。因此正确做法是：用卡片标题定位候选 → 点开该卡片的「立即铺货」读出 offer 链接 → 用这个链接做 `prepare`。

不要用标题去 1688 人工检索来"猜"同一个商品——已有精确 ID 时那是多余且容易出错的一步。`candidates` 本身不点任何按钮、不创建任何商品。

## 审核状态与复制历史（只读）

```powershell
doudian-auto --json dropship product-status --product-id '<抖店商品ID>'
doudian-auto --json dropship history-dump --out '<输出.json>'
```

`product-status` 读一个商品在抖店的**平台状态**：已提交的商品在商品管理页、状态词是「售卖中 / 已下架 / 审核驳回 / 审核中」；未提交的草稿在草稿箱页、状态词是「待提交」。**两页互斥**，所以程序会两页都查。两页都没有这个商品 ID 时，程序如实报「无法确认审核状态」——

⚠️ 这与「未提审」不是一回事：「未提审」是妙手侧用词，含义是「从没提交过审核」；「查不到」还可能是商品已被删除。**不要把两者混着汇报**。

⚠️ 「**已下架**」**不等于**「审核驳回」：点行内「查看原因」给的是具体原因（本项目商品实测是「**商家自主下架**」），而真正的平台驳回在商品管理页的「审核驳回」分类里（`rc-tabs-0-tab-releaseRecord_fail`），两者是不同的分类。核对状态要逐个点开分类 tab 看「送审时间 / 通过时间 / 驳回时间」，不要只读行内状态词。

本项目「发布商品」这条路径的实测终态是「**审核通过但未上架**」（通过时间 == 下架时间 == 商家自主下架）。**上架是独立的对外经营动作**：行内有「上架」按钮，但没拿到明确授权不要点，报告里如实写「审核通过、当前未上架」。

类目必填属性可能是「文本」「单选」也可能是「**数值 + 单位**」的复合控件（如保质期）。平台会预选单位，**单位标签存在不等于已填**，判「已填」要看数值非空；单位候选要从真实下拉里读出来校验，不能猜。

`history-dump` 采全量复制历史行（页面是虚拟滚动＋分页器，读一屏只能拿到一部分）。返回的 `total_on_page` 是页面自己写的总条数，`collected` 是实际采到的条数，`complete` 表示两者对得上。做统计或汇总时用 `history-dump`，不要用只读一屏的结果当全量。

## 准备与价格确认

```powershell
doudian-auto --json dropship prepare `
  --source-product-id '<1688来源商品ID>' `
  --offer-url '<1688商品链接>' `
  --shop '<店铺>' `
  --source-price '<源价>' `
  --multiplier '<倍数>' `
  --addition '<加价>' `
  --source-title '<来源商品标题>' `
  --category '<已知抖店类目>'
```

`prepare` 不连浏览器、不执行页面写入。核实返回的来源商品、店铺、类目预检和价格试算。

- 价格试算**只是人工确认参考**，不含页面运费与尾数，不等于最终售价。向用户展示源价、公式和试算结果，进入写入阶段前取得明确确认。
- 页面的 `pricePercent` 是百分比（300 表示 300%），任务的 `multiplier` 是倍数（3 表示三倍），**差 100 倍**。程序已换算，但人工核对时别把两者混同。
- 类目预检命中高风险时，先查明实际目标类目及必填属性。只有经人工核实并明确接受风险，才可重新创建计划并使用 `--allow-risk`；它不是通用跳过检查开关。
- 人工补值清单里的值必须由人按真实资料提供，不能猜、不能从相似商品借。

## 阶段执行

使用 `prepare` 返回的 `task_id`，按程序返回的阶段和下一步提示推进：

```powershell
doudian-auto --json dropship apply '<task_id>'          # 预览，不写入
doudian-auto --json dropship apply '<task_id>' --apply  # 按阶段推进
doudian-auto --json dropship verify '<task_id>'         # 只读核查
```

阶段含义：

- `prepared`：计划已建立；搬家配置尚未确认写入并读回。
- `settings_verified`：配置已重新进入页面独立读回且一致，才可能进入复制阶段。
- `unknown`：复制动作结果不确定。**只允许只读恢复与核验**。
- `copied`：从复制历史确认目标商品已创建；仍需核查目标商品页。
- `copy_confirmed`：程序已能证明「复制产生了这个商品且定价符合公式」。**不表示审核通过、已上架或消费者端生效**。
- `verification_pending` / `blocked` / 明确失败：按程序给出的原因停止并报告，不能手改状态推进。

仅在价格、商品、店铺、类目与写入意图均已核实并获确认后，才运行带 `--apply` 的命令。每次执行后读取返回状态，不跳过阶段。

## 会话自检（只读，跑任何写操作前）

```powershell
doudian-auto --json dropship session-check --session '<会话>'
```

浏览器会话过期时，抖店与妙手页面都会跳到登录页。此时程序会在页面动作前直接报 `dropship_login_required`，**不会代登录，也不会在登录页上重放写操作**。遇到这个错误：让用户自己在浏览器里重新登录抖店，再重跑同一条命令；不要改任务 ID、不要换参数绕过、不要手动推进状态。

## 人工待办汇总（只读）

```powershell
doudian-auto --json dropship manual-queue
doudian-auto --json dropship manual-queue --data-root '<其它任务根目录>'
```

把「铺货任务缺的类目必填属性」与「批量队列里因属性缺失而 blocked 的商品」汇成一张只读清单。它不修改队列状态、不解锁任务、不写商品页面，只回答「还欠哪些值、分别属于哪个商品」。

报告还给出队列 blocked 的**原因分类**（如需重新基线、必填属性缺失、图片槽位不足、视觉质量、商家编码不完整等）与「该谁处理」标记，据此分诊，不要把所有 blocked 都当成「缺属性」。

## 失败关闭与人工确认

- 预检、页面识别、唯一性检查、配置读回或目标读回不通过：停止该任务，保留任务和证据，按程序给出的错误处理。
- 结果为 `unknown`、命令超时、断连或窗口异常：只运行 `verify` 或按程序提供的只读恢复路径。**不得重发 `apply --apply`**，不得换任务 ID 重做以绕过未知结果。
- 类目高风险、必填属性缺少真实依据、价格/运费/最终售价理解不清：暂停并取得人工确认，不用默认值猜填。
- 复制完成后只报告程序实际证实的字段和未验证项。不得把 `copy_confirmed` 表述为审核通过、上架成功或消费者端生效。
- 保留任务目录、错误信息和核验结果供续办；不得清理或覆盖未知任务的证据。

## 禁止事项

- 不批量调用此单商品流程，不并发对同一商品或同一浏览器会话写入。
- 不猜测页面动作，不绕过程序预检、状态机、锁或唯一性闸门。
- 不因结果未知而重复复制，不手工修改任务状态来解锁。
- 不把人工补值清单当成属性值来源；只依据商品真实资料或用户确认填写。
- 不把程序预览价当作页面最终价，不自行承诺页面未读回的价格。
- 不把「复制已确认」说成「已审核、已上架或已生效」。
- 页面选择器、DOM 结构、具体页面契约和状态机内部字段属于程序实现细节；以当前 CLI 输出、错误及项目维护文档为准，不要在 skill 里复述。
