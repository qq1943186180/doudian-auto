# 妙手商品编辑

使用妙手编辑指定商品，以妙手新页和抖店独立读回确认结果。此技能规定单品页面操作和人工证据记录；当前 `doudian-auto batch` 是另一条有持久状态及程序闸门的路径，按 `miaoshou-auto-batch` 执行，不能把其自动锁和验收套用到手工弹窗。

## 授权、入口与模式

- 记录店铺、字符串商品 ID、目标字段/版本及动作。仅“改一下”且保存意图不清楚时先准备方案，发布前确认；已明确授权保存/发布或完成固定队列时沿用授权，无需逐页重复询问。每次最终保存前记录并展示店铺、ID、最终标题、目标图片槽位/数量、保护字段及是否包含上架，核对仍属该版本和原授权。
- 图文保存与上架是不同动作；上架须包含在用户明确任务范围内。价格、库存、SKU、类目、品牌、履约售后、3:4 图、白底图默认保留。类目变更必须有针对目标类目的明确授权；缺失事实请用户补充，平台推荐不能当事实或授权。
- 平台新增必填属性仅在现有授权覆盖下，依据该商品真实资料、SKU、原图或用户确认补齐，并记录值及来源；保护字段或服务条款变化另核对授权。批量程序拦截的缺项按其正式流程解决，不能改状态绕过。
- 首页 `https://v2-dd.chengji-inc.com/home`，快速编辑 `https://v2-dd.chengji-inc.com/product/quick_edit`。链接、选择器和控件以当前授权页面为准，不猜写接口。
- 浏览器通道默认 **Ego 原生**（`--endpoint` 默认即 `ego`），先读当前 `ego-browser` 文档用其原生 TaskSpace/Page 接口。Kimi WebBridge 只是显式选用的兼容通道（传 `--endpoint http://127.0.0.1:10086`），只有选用它时才读参考文件的 Kimi 协议示例。通道不可用先完成离线素材，持久化阻塞；不搬用其他任务页、不切换通道绕过未知提交。

## 开工和基线

1. 检查项目 HANDOFF、当前任务及其他已知项目工作区的 `work/miaoshou-jobs/` 手工记录、批量队列以及 `~/.doudian-auto/jobs/` 中同商品的 manifest/state。存在编辑、占用或未知提交先核对归属，单一操作者串行处理。直接 CLI 与当前批量 Writer 在同一 DATA_ROOT 下共享 browser.lock，但本手工路径不受其保护；人工交叉检查不能消除检查后的并发竞争。
2. 清理本项目遗留页面，未完成页面先保存续办证据。仅关闭自己任务所属页面，保留其他用途页面。
3. 建立 `work/miaoshou-jobs/<商品ID>-<版本>/`，记录目标计划、原始基线、素材 SHA256、上传映射、授权及提交/读回证据；详见 [状态与核验](references/recovery-and-verification.md)。标题或素材变化记录新版本，不覆盖旧证据。
4. 新开快速编辑页，核对店铺，按精确商品 ID 查找并打开该行“编辑商品”，弹窗再次核对 ID。进入前读 [浏览器操作](references/browser-workflow.md)，避免相似标题/第一行匹配。
5. 读取标题、完整图片顺序、全 SKU 及商业字段、草稿/驳回/审核状态；版本或归属不清楚先调查。保存前取得相同商品的独立抖店基线，不把草稿或未保存输入作为线上值。缺字段、虚拟 SKU 未读齐或加载中空值记覆盖缺口，不能当成相等。

## 文案与图片

- 标题和卖点以真实商品资料为依据。可选免费课程检索：`GET http://127.0.0.1:5001/api/rag/search?q=<URL编码的问题>&limit=5`；可选 `platform/market/source_type` 筛选按服务实际值填写。设置 5 秒超时、失败最多重试一次，再用已确认资料继续并记录降级；默认不调用收费 `/api/rag/ask`。其他平台或 general_fallback 只作方法参考。
- `doudian-auto --json title check --title '<最终标题>'` 离线检查。需要事实诊断时读取已安装 `doudian-product-workflow` 的 `references/environment-and-facts.md` 获取 schema；缺少该技能或 CLI 时使用当前页面规则和真实事实逐项检查并记录未运行本地校验。**妙手标题修改在妙手完成，不用 title apply 代替。**
- 只改标题不重传图片；部分替换只改指定槽位，保留详情尾图和其他主图。完整素材校验可使用同仓抖店技能的 `scripts/doudian_check.py`，通过可导入 `doudian_auto/Pillow` 的项目 Python 及脚本真实路径执行；其五方主图规则只适用于完整素材集。
- 新图逐张参考真实原商品生成，检查身份、结构、颜色、数量、印字及规格。已有合格素材直接复用；不以原图复制或排版拼图冒充要求的新生图。妙手自带 AI 功能可能耗额度，需另有相应授权。

## 编辑和保存

1. 完整基线后先持久化 editing，再填写“商品标题”，避开短标题、备注和参考价；输入后读取当前值确认。
2. 主图按“商品主图”分组逐槽替换，详情按明确位置/顺序替换；每次上传后读取远端结果，记录本地哈希与槽位/远端对应。没有对应证据不跳过也不盲目重传。
3. 不随手启用“同时替换相同图片”、AI 属性、托管或店铺级同步开关。保存可能涉及整个商品；预览核对全部目标字段、非目标图片和商业字段，未知差异停止。
4. 在授权范围核对完成后，先串行写完 `state.json` 的 submitting/unknown 和 `submission.json` 的提交意图，回读确认店铺/ID/版本及内容后，才能向浏览器发出单次“保存到抖店”点击。文件写入失败或回读不符停止，不将落盘与点击并行；随后记录真实响应、任务 ID、结果及时间。
5. 超时、断连、窗口消失或不明提示进入只读核查；不以刷新、换工具、换任务或旧内容读回来重发。编辑中断、明确失败和未知提交分别按恢复参考处理。

| 任务记录状态 | 下一步 |
|---|---|
| prepared | 建立新鲜基线后编辑 |
| editing / uploaded，未保存 | 核对当前页面及原证据，续原版本；最终预览通过后按授权保存 |
| submitting / unknown | 只读历史任务及双端读回，禁止重发 |
| submitted | 只读核验，待审核版本与已生效版分别记录 |
| verified | 报告覆盖范围；不因后续上下架变化重复保存图文 |
| rejected / failed | 确认上一尝试结束且无待处理提交，再按修正授权处理 |

此表是单品人工证据约定，不能手改批量队列 state 以套用它。

## 独立核验与收尾

从妙手新页重读相同商品，再从当前页面实际官方编辑入口独立读取抖店。可用 `doudian-auto --json read --url '<实际链接>' --shop '<店铺>' --out '<读回.json>'`，但其快照与妙手结构不同，需要按字段映射比较；不能把妙手目录交给抖店 upload/submit/verify。

逐项核对精确标题、图片内容/顺序、非目标图片、全部可观测保护字段及 SKU；不靠数量或列表缓存判成功。URL 参数变化结合资源和远端内容判断，不随意全部去掉。保存受理、后台读回匹配、审核中、消费者端生效分别报告；缺受理证据时不补写历史点击成功。未知保存的旧生效版不是失败证明。

证据、图片、登录信息留本地；按项目要求维护 HANDOFF/T-ID、回写 Issue 并读回。每轮结束先持久化可续办状态，再关闭本轮用完的项目标签；其他用途标签保留。缺登录/验证码时交用户处理；不自动回滚已受理商品。
