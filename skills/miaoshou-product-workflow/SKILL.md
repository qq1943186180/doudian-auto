# 妙手商品编辑

以妙手作为商品编辑界面，以抖店独立读回作为最终核验。默认只修改授权商品的标题、方主图和详情，保留 SKU、价格、库存、类目、品牌、物流、售后、3:4 图和白底图。

## 当前能力与入口

- 这是**浏览器工作流 skill**，不是已经实现的妙手上传 CLI；不存在 `miaoshou-auto` 命令。不得把原抖店程序的自动锁、断点恢复或测试结果宣称为妙手已有能力。
- 2026-10-24 已按用户指定商品完成实测：本地主图上传、图片链接导入、5 张方主图及 4 张详情逐槽替换、单次保存成功，以及新页妙手/抖店双端读回；24 个 SKU 和商业字段保持一致。标题原值已满足目标而保留，**不同标题写入、批量连续处理、保存断连恢复尚未实测**。细节见两个参考文件；不把单款成功扩大成所有能力已验收。
- 首页：`https://v2-dd.chengji-inc.com/home`；快速编辑：`https://v2-dd.chengji-inc.com/product/quick_edit`。不猜独立编辑 URL、提交接口或商品类目参数。
- 浏览器使用本机 `kimi-webbridge` skill 和当前 Edge 登录态。先读其工具协议，连接失败用 `kimi-webbridge-boot`。保留当前任务的 session；另一个独立任务使用自己的 session，不抢占其他任务编辑页。
- 进入编辑页前读 [浏览器操作](references/browser-workflow.md)；编辑、保存、恢复前读 [状态与核验](references/recovery-and-verification.md)。

## 开工与任务范围

1. 确认目标店铺、商品 ID、要改的字段、最终素材与是否包含保存发布。沿用会话已有授权，不因正常换页或首次执行重复索要批准；创建 skill 本身不授权改商品。
2. 检查项目 HANDOFF、已有妙手任务记录及 `~/.doudian-auto/jobs/` 中同商品的真实 manifest/state。发现其他任务正在编辑、上传、提交或提交结果未知，先核对并续办原任务，不靠换渠道绕过占用。现有抖店锁不会自动锁住妙手，需明确单一操作者并串行处理。
3. 在当前任务工作区的 `work/miaoshou-jobs/<商品ID>-<版本>/` 保留计划、基线、素材 SHA256、上传对应关系、提交记录和读回结果。`<版本>` 是该次不可变目标的标识；更换标题或素材需记录新版本，不能覆盖旧提交证据。
4. 用新打开的快速编辑页建立基线，避免把别人未保存的输入当成线上数据。核对页头店铺名，按商品 ID 查询，再在含完整目标 ID 的那一行点“编辑商品”；弹窗再次核对 ID、标题与图片。不以列表第一行、活动页签或商品名称相似为依据。
5. 记录原标题、全部目标图片的顺序、SKU 规格及价格库存、类目品牌、物流售后、3:4/白底图和审核/草稿状态。首次保存链路及读取版本不确定时，编辑前先取得抖店独立基线，查清两边差异。记录采集来源、时间和覆盖缺口；加载中的空值不能作为“原值为空”。草稿、驳回或他人改动先查明归属，不覆盖未知修改。

## 文案与素材准备

- 从该商品真实资料和 SKU 建立事实；标题/卖点可先检索 `http://127.0.0.1:5001/api/rag/search`，设置超时，失败重试一次后降级。默认不使用收费 `/api/rag/ask`。
- 标题复用现有本地规则：`doudian-auto --json title check --title '<新标题>'`；有事实文件可加 `title diagnose --title '<新标题>' --facts '<事实.json>'`。这两条不写店铺；**不要运行 `title apply` 来代替妙手编辑**。
- 只改标题时不要准备、删除或重传图片；只换指定槽位时保留其他槽位。整套改版通常为 5 张方主图和明确数量的详情；部分修改不强行补成 5 张，不顺便改 SKU 图或 3:4 图。
- 整套素材可复用 `doudian-product-workflow/scripts/doudian_check.py assets`，必须用已安装 `doudian_auto` 的项目 Python；其命名和数量要求只适用于完整素材集。单槽替换则核对所替换文件的格式、尺寸、大小、哈希与页面当前限制，不通过重传全套来迁就校验器。
- 需要新生图时使用当前可用的 imagegen 工作流，参考原商品逐张生成并目视检查。不能用拼图排版冒充 AI 重构；已有合格素材直接上传。妙手“AI换图/AI换标题”是另一项可能消耗额度的操作，不自动点击、不把软件订阅当作无限生成授权。
- 准备和验图在删旧图之前完成。事实、文字、主体、颜色、数量、规格必须一致。

## 在妙手编辑

1. 保存完整基线后，在任何字段写入前记录阶段 `editing`。这是 agent 维护的证据记录，尚无独立程序强制执行。
2. “商品信息”页签填写主标题，避开导购短标题、备注和参考价。输入后核对当前值，不因多个“请输入”同名而盲填。
3. “主图”页签优先逐槽“替换”，只操作“商品主图”组。每次上传后确认目标槽位已对应本地文件，记录新远端地址和顺序。需要增删数量时先核对正确分组、现有数量和最终计划，不能根据删除按钮的全局序号操作。
4. “详情图”页签支持“上传图片”→“上传/替换图片”→本地上传或图片链接。选择输入方式后确认缩略图及顺序；全量替换要明确旧图删除与新图插入的边界，避免追加成旧图+新图。部分替换保留非目标图片。
5. 上传与弹窗确认串行执行，等待已加载的远端结果。没有读取并核对新状态前，不重复上传同一张；上传失败也不能推断文件完全没有入库。
6. 不随手改变“同时替换/删除相同的图片”、AI 推荐、属性自动填写、托管、货源同步等设置。检查这些设置是否会影响目标；如有未知连带影响先调查，不静默修改店铺级开关。
7. 最终预览与计划逐项核对：标题、目标槽位、新旧图片对应、详情数量和顺序、所有非目标商业字段。**独立页签不代表独立保存**，保存可能涉及整个商品；字段缺失或未知差异不能当作通过。

## 保存与抖店核验

1. 确认最终保存包含在当前授权范围内。素材生成、进入弹窗、上传或点图片窗口“确定”均不等于商品已保存。
2. 点击“保存到抖店(F)”**之前**持久化 `submitting/unknown`，包含目标商品、版本、时间和编辑后证据；每次提交尝试只点击一次，记录实际提示、任务 ID、成功/失败或未知。
3. 保存超时、断连、窗口消失或出现不明确提示时，进入只读核查。不能换任务、刷新后再点保存或转抖店直接发布来“重试”。处理方式见恢复参考。
4. 妙手重新打开相同商品，读取保存后的版本；再从实际页面取得的“抖店编辑/去抖店编辑”链接独立读回。已有 `doudian-auto --json read --url '<实际链接>' --shop '<店铺>' --out '<读回.json>'` 可用于抖店只读采集，但其 JSON 格式不能直接当妙手快照比较。
5. 比对目标标题、图片内容对应及顺序、非目标字段；完整观察后才能记“读回已核验”。图片数量相同不证明内容相同；详情显示 0×0 不证明没有图片。CDN 地址变化要区分处理参数与真正换图，不随意丢弃可能标识资源的参数。
6. 分开报告：素材完成、已上传未保存、妙手保存受理、抖店读回匹配、审核中、消费者端生效。抖店返回旧生效版而新版本在审核时，保留两个版本及状态，等待后只读复查，不重复提交或覆盖证据。

## 收尾与边界

- 按项目约定保存截图、核验 JSON、简短 HANDOFF 与 T-ID 映射，并回写相关 Linear Issue 后读回。商品数据和登录信息不进 Git。
- 标题、方主图、详情之外的批量价格库存、上下架、删除、类目、履约或营销任务，只有明确授权时才扩展范围，并先观察对应界面及字段核验方法；本 skill 的图文路径验证不能冒充这些能力也已验收。
- 不导出 Cookie/登录凭据，不借用页面内部框架状态；结构化读取仅使用当前授权页面的实际网络响应或 DOM。不要猜测或重放未经观察的写接口。
- 不关闭其他人的商品页或带未保存内容的页面；任务标签只在用户要求时关闭。验证码/登录交由用户处理。异常恢复不自动回滚已受理的商品。
